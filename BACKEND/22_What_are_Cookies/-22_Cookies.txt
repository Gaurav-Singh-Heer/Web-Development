1) Cookies:-
|   In cookie case we do.  res.cookie
|
|   We made a cookie in which we have client data (uid,token) and gave cookie to user.
|
|   Now in Browser we make cookie in which we have our uid. Now whenever we send any request to user.
|   Let's say request is at "/user" we don't know whether it's get or POST. Then these cookie will also
|   go along
|   
|   To Check if user is logged in or not we will check whther there is uid name in cookie. If not then 
|   user is logged out. Else user is logged in.
|   If There is uid name in cookie then we will take it out from cookie and Validate it to check whether
|   it's the same token we made and when we will inspect the cookie we can see all information of the user
|
|                               +++++++++++++++++++++++++++++
|
|--> WHAT IS INSIDE COOKIES:-
|   -Cookies are basically::1) domain specific means there is domain attached
|
|   1) Domain Specific/attachment means, let's say I am a client and i have a browser.
|                                                  I logined at facebook and (fb.com) created (2)cookies for me
|
|                                        let's say now u requested at piyushGarg.dev and it also requested some (2)cookies
|
|                                        Now we have total 4 cookies :- 2 from fb and 2 from piyushGarg
|
|                                        Now when i search at piyushGarg.dev then only cookies of piyushGarg will be shown
|                                        Similar at facebook.com
|
| This is because if all cookies are shared then owner of site will get access of your all data at other 
| sites too which is not a good thing
|
| So, With cookie there is a domain (name of site) so that cookies of only particular site is shown to a
| person. As shown Below:-

Token 
|   res.json({token})  by this token is sent to user file.
|
|   we can send this token using. Route
|
|   Route:- header:{Token:token}
|           or we can use standard way in which we have built in header known as authorization
|           header:{Authorization:"Bearer<token>"}
|
|   More at :- https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Authorization
|
|   Bearer:- https://swagger.io/docs/specification/v3_0/authentication/bearer-authentication/
|           
|               Use:- Authorization: Bearer <token>  // will ignore bearer and use token only
|
|               +++++++++++++++++++++++++
