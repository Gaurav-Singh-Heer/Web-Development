-->(Real Life Example 1:)

--> Story:- Let's say a person wants to park a car at the parking at the mall
|           So, Person takes his car to the valley(parking boy) and ask him to park his car. Valley parks the 
|           car and gives the ticket.
|
|           PARKING TICKET:-  Number 24               (Valley Gave TICKET to person)
|           Number 24: DLXXXX123                      (Valley wrote in it's Diary )
|
|           After, My person completed his work at the mall then person return to the parking
|  
|           PARKING TICKET:-  Number 24               (Person Gave TICKET to Valley to get car back)
|           Number 24: DLXXXX123                      (Valley opened his diary to check the Number of car with TICKET No. 24)
|
|           Valley Gave Car Back to the Person.
|           
|           Number 24: DLXXXX123                      (Valley Deleted this entry from Diary)

|--------: So, now the Valley's Diary where he had all entries Like,
|
|           Number 24: DLXXXX123                     -----------------------
|           Number 23: DLXXXX146                                            |
|           Number 25: DLXXXX134                                            |------------ This Data Entry By Valley Is called as STATE
|           Number 26: DLXXXX167                                            |
|           Number 27: DLXXXX123                     -----------------------
|
|         This thing is called Statefull as here a STATE is maintained


-->(Real Life Example 2:)

-->STEP 1:- CLIENT  --------------------- Username/ Password (for LOGIN)-------------> SERVER
|  STEP 2:- CLIENT  <-------------------- Session UID (uid: 367) --------------------- SERVER       || Server creates a unique id for the user and give it to him          
|  STEP 3:- CLIENT  --------------------- Get / users | uid: 367 --------------------> SERVER       || Here we sent get request to the server and sent uid along           
|  STEP 4:- Server Checking who is user 367                                                         || Server found that CLIENT(Piyush) is a logged in user and an admin
|  STEP 5:- CLIENT  <-------------------- response: all user-------------------------- SERVER       || As Server found that piyush is logged in user and an admin so server sent the response tp access details of all users to the CLIENT         


--> How to transfer UID?

|     Server can send the UID to the CLIENT in 3 ways:- Cookies, Response, Headers.
|     
|                  <---------------------- Cookies ------------------------------->      
|           CLIENT <---------------------- Response ------------------------------> SERVER
|                  <---------------------- Headers ------------------------------->
|
|     In Server Side Rendering done in EJS where we directly talk to server there we find Cookies as a good option      
|     But in Rest API we use Headers more
|
|     So, Let us say if we have a mobile application then it will send token(unique ID) in Headers.
|     But now as we are using Browser so, we will use Cookies.


---> EXPRESS FLOW

|         CLIENT ------------------> Auth Middleware -------------------------> Endpoint Route
|                                 Check for cookie value 
|                                 or uid, if valid calls
|                                 next() else rejects the 
|                                 request

async function checkAuth(req, res, next) {            // This will not do any forceful work it will only check if user is login then ok else also ok
    const userUid = req.cookies?.uid;   

    const user = getUser(userUid);
    
    req.user = user;
    next();
}
