|                   Both <h2> and <h3> will be displayed on the same line because of the display: inline; style applied to them. Here's why:
|                   
|                   Block-level elements (such as <h2>, <h3>, <p>, etc.) by default take up the entire width of their parent container and force the next element to start on a new line.
|                   Inline elements (such as <span>, <a>, etc.) only take up as much width as necessary and allow other elements to appear beside them on the same line.
|                   By using display: inline; on both <h2> and <h3>, you're telling the browser to treat these heading tags as inline elements, which don't force line breaks and instead stay on the same line, if there's enough space.

<% if (locals.user) { %> <% } %>

Here, Locals means... locals is an object if we write <%= JSON.stringify(locals)%> it will print object

---> <% if (age) { %>........ <% } %>, if we write age then there would be error as we haven't passed any age variable

---> But if, <% if (locals.age) { %> <% } %>, then there would be no error as system will find in it's local whether age is present or not.

|                       Case 1: <% if (age) { %> ... <% } %>
|                       -------------------------------------------------
|                       - Assumes `age` is a defined variable in the current context.
|                       - If `age` is NOT passed or defined, it will throw a `ReferenceError`.
|                       - Example of error:
|                         "ReferenceError: age is not defined"
|                       
|                       Case 2: <% if (locals.age) { %> ... <% } %>
|                       -------------------------------------------------
|                       - Safely checks the `locals` object for the `age` property.
|                       - If `age` is NOT defined, `locals.age` will be `undefined` or `false`.
|                       - No error will be thrown, and it handles missing variables gracefully.
|                       
|                       Why use `locals`?
|                       -------------------------------------------------
|                       - `locals` is an object that contains all local variables available in the EJS template during rendering.
|                       - It avoids runtime errors caused by missing variables.
|                       - Ensures templates handle undefined variables gracefully.
|                       
|                       Example using `locals`:
|                       -------------------------------------------------
|                       <% if (locals.user) { %>
|                         <p>Welcome, <%= locals.user.name %>!</p>
|                       <% } else { %>
|                         <p>Welcome, Guest!</p>
|                       <% } %>
|                       
|                       Behavior:
|                       - If `user` is passed as a variable, it will render:
|                         "Welcome, [User's Name]!"
|                       - If `user` is NOT passed, it will render:
|                         "Welcome, Guest!"
|
