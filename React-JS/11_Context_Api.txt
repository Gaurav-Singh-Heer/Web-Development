Why do we need Context API:-
Suppose we made an App in React and we have some components and we are rendering them A inside B , C inside B, D inside C.

|Component A ----
|               |
|               V
|          Component B ----
|                         |
|                         V
|                   Component C ----
|                                  |
|                                  V
|                               Component D ----
|                                              |
|                                              V

Now lets say we have a state :-
with key as :- Value 1 and setCount()

Now lets say this state is present at Component A and we have to Access it from Component B.

Way 1 :- Give this state From Component A to Component B through Prop
|        Component B will give this to Component C through Prop
|        Component C will give this to Component D through Prop. So, this is the way 1 to Drill Down the state From A to D 


This is Prop Drilling we should not do this because if we have to render this Component D to another component due to which we have to change our whole component tree which is a Bad Practice
![Way 1](./11_Context_API/Screenshot/1.jpg)


To Solve this problem we use Context API 

---

Now, will see how context API will Handle Above Problem:-

![Way-2 By Context API](./11_Context_API/Screenshot/2.jpg)

Way 2 :- Here we will keep that state in Context (React-Context) Now Component A can also access it and
|        also Component D can access it. Without any Prop Drilling
|        Now Both Component A and D can Read and write the State inside the Context
|        As no Prop-Drilling So we can render Component D anywhere in the Component Tree as Now it is not 
|        Dependent on Component A for the State. Now if Component A Changed it's State then Component D 
|        will Also Re-Render. 
|        This is Beauty of Context that if component A Changed itself Component D will Auto render itself. 

To give access of context to components we have to wrap them inside context provider

![Way-2 By Context API](./11_Context_API/Screenshot/3.jpg)

If we not did this then these components cannot access this context

Now all components A,B,C,D are wrapped inside this context Provider and they can read and Write this Context.

import {createContext, useState} from 'react'

export const CounterContext = createContext(null);
export const CounterProvider = (props) => {
    const [count, setCount] = useState(0);
    return (
        <CounterContext.Provider value={{ count }}>
            {
                props.children
            }
        </CounterContext.Provider>
    )
}

Summary:-

We made a Context. By createContext which we use in React then we made a provider of Counter so that we can give access to our App-Component of this particular Context.
So, we made a Provider in which we wrapped all the child as CounterContext.Provider

So, if we go at main.jsx there we rendered CounterProvider inside that the App-Component will 
render at props.child of context/Counter.jsx thenwe added 3 values at our CounterProvider 
(count, setCount, name) a function to update our count and 3rd we added name for testing called 
Piyush
At app.jsx we imported useContext from react to read the value of Context from react and the we imported our actual context "./context/Counter" over there and we consoled the output then on increment and decrement without using prop at Component/Counter.jsx we directly used the state from useContext then at there we called setCount function and incremented and decremented the value of Count from reading it from counterContext.count.
So, we made a direct connection and we haven't done anytype of pop-passing or pop-drilling.
